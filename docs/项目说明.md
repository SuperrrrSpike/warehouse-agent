# 仓储运营分析与波次负荷预测：项目说明

## 1. 业务问题

仓储管理者既要监控任务、机器人和站点运行情况，也要在波次释放前判断哪些任务可能产生较高拣选负荷。本项目把“事后运营诊断”和“事前波次容量规划”放在同一条本地、可审计的数据链路中。

## 2. 系统设计

- **运营分析**：用 SQLite 和参数化 SQL 计算完成率、吞吐、利用率、空跑、排队、异常与拥堵指标。
- **真实数据处理**：关联订单、拣选波次、商品和库位表，将 337,562 条订单/拣选记录聚合为波次级特征。
- **训练评估**：只使用执行前可获得的订单规模、库位空间分布和商品结构特征；按时间切分，使用验证集选模型、测试集作最终评估。
- **决策输出**：输出预测负荷、规划区间、四级风险和班前行动建议，不自动下发生产指令。
- **治理**：记录数据 SHA-256、模型版本、依赖版本、误差分层、特征重要性和使用边界。

## 3. 当前可验证结果

- 真实拣选明细 215,192 行、客户订单 122,370 行、波次 9,707 个。
- 经过库位关联、日期校验与质量门槛后，有效训练波次 8,185 个。
- 对比 Ridge、Random Forest、HistGradientBoosting 后，验证集选择 HistGradientBoosting。
- 测试集 R² 为 0.845、MAE 为 368.2 布局坐标单位；MAE 相比中位数基线改善 65.8%。
- 生成高负荷/关键波次任务队列、预测规划区间和响应式模型看板。

## 4. 面试演示顺序（3–5 分钟）

1. 打开 `reports/ml-wave-workload-dashboard.html`，说明真实数据规模与时间外推评估。
2. 展示候选模型比较，强调模型选择只使用验证集，测试集保留到最后。
3. 解释 `y_range`、`x_range`、巷道数和唯一库位数为何影响路线负荷。
4. 打开 `reports/wave_action_queue.csv`，展示预测如何转化为拆分波次、错峰释放或资源复核建议。
5. 打开 `models/route_distance/MODEL_CARD.md`，主动说明代理目标、库位缺失和生产上线门槛。

## 5. 简历表述

推荐使用下面两条，避免把代理指标夸大成真实工时预测：

> 独立开发仓储运营分析与波次负荷预测系统，清洗并关联 21.5 万条真实拣选记录、12.2 万条订单及商品/库位数据，构建 21 项波次级特征和可复现的数据质量流水线。

> 采用时间顺序 70/15/15 切分比较 Ridge、Random Forest 与 HistGradientBoosting，最终测试集 R² 达 0.845、MAE 较中位数基线下降 65.8%；输出四级负荷预警、预测区间、班前行动队列及模型卡。

技术栈：Python、pandas、scikit-learn、SQLite、SQL、HTML/CSS、unittest。

## 6. 不能夸大的部分

- `route_distance_proxy` 是基于仓库布局和原始拣选顺序构造的距离代理值，不是实际工时。
- 当前结果来自公开真实数据集的离线验证，并非已经在商业仓库生产部署。
- 行动建议用于人工复核；没有验证自动拆单、自动排班或自动调度的实际收益。
